# Understanding the Planning of LLM Agents: A Survey

## 一、引言（Section 1）
1. **研究背景**
   - 自主智能体的定义：通过感知环境、规划和执行动作来完成特定任务的智能实体
   - 规划是智能体最关键的能力之一，涉及复杂的理解、推理和决策过程
   - 规划任务的一般形式化表达：$p=(a_0, a_1, \cdots, a_t)=\text{plan}(E, g; \Theta, P)$

2. **传统方法的局限性**
   - 符号方法（如 PDDL）：需要将自然语言问题转换为符号建模，依赖人类专家，缺乏容错性
   - 强化学习方法：需要大量样本（与环境交互），在数据收集成本高的场景中不切实际

3. **LLM 带来的范式转变**
   - LLM 在推理、工具使用、规划和指令遵循等方面展现出显著智能
   - 启示了将 LLM 作为智能体认知核心的潜力

4. **研究意义与创新点** ⭐
   - **首个从规划能力角度系统分析 LLM 智能体的综述**
   - 提出了新的五分类法体系
   - 在四个基准上对代表性方法进行了实验评估

## 二、分类体系（Section 2）

1. **五大方向总览** ⭐
   - **任务分解（Task Decomposition）**：分而治之，将复杂任务拆解为子任务后逐一规划
     - 公式：$g_0, g_1, \cdots, g_n = \text{decompose}(E, g; \Theta, P)$；$p_i = \text{sub-plan}(E, g_i; \Theta, P)$
   - **多计划选择（Multi-plan Selection）**：生成多个候选计划，通过搜索算法选择最优
     - 公式：$P = \{p_1, p_2, \cdots, p_n\} = \text{plan}(E, g; \Theta, P)$；$p^* = \text{select}(E, g, P; \Theta, F)$
   - **外部规划器辅助（External Planner-Aided Planning）**：LLM 负责任务形式化，外部规划器执行规划
     - 公式：$h = \text{formalize}(E, g; \Theta, P)$；$p = \text{plan}(E, g, h; \Phi)$
   - **反思与优化（Reflection and Refinement）**：通过反思失败经验来改进计划
     - 公式：$p_0 = \text{plan}(\cdot)$；$r_i = \text{reflect}(\cdot)$；$p_{i+1} = \text{refine}(\cdot)$
   - **记忆增强规划（Memory-Augmented Planning）**：利用额外记忆模块存储和检索辅助信息
     - 公式：$m = \text{retrieve}(E, g; M)$；$p = \text{plan}(E, g, m; \Theta, P)$

2. **方向间的关系**
   - 五个方向相互关联而非互斥，常涉及多种技术的联合采用

## 三、任务分解（Section 3）

1. **先分解方法（Decomposition-First）**——先拆解任务，再逐个子规划
   - **HuggingGPT**：LLM 作为控制器，显式指令拆解多模态任务为子任务，提供任务间依赖关系
   - **Plan-and-Solve**：将"Let's think step-by-step"改进为两步提示——"先制定计划"再"执行计划"
   - **ProgPrompt**：将自然语言任务转化为代码问题，动作形式化为函数，对象表示为变量

2. **交错分解方法（Interleaved Decomposition）**——分解与子规划交替进行
   - **Chain-of-Thought (CoT)**：揭示 LLM 的少样本推理能力，通过构造轨迹引导推理
   - **Zero-shot CoT**：以"Let's think step-by-step"解锁零样本推理
   - **ReAct**：解耦推理与规划，交替执行推理步骤和动作步骤
   - **Visual ChatGPT**：基于 ReAct 机制，LLM 配备视觉模型处理图像任务
   - **PAL**：利用 LLM 编码能力，引导生成代码进行推理，由代码解释器执行
   - **Program-of-Thought (PoT)**：将推理过程完全形式化为编程，借助 CodeX 模型提升性能

3. **讨论**
   - 先分解方法优势：子任务与原任务关联性强，降低任务遗忘和幻觉风险
   - 先分解方法局限：子任务预先确定，单步错误可能导致整体失败
   - 交错分解优势：根据环境反馈动态调整分解，提高容错性
   - 交错分解局限：过长轨迹可能导致 LLM 幻觉，偏离原始目标
   - 共性挑战：额外的时间与计算开销；高复杂度任务受上下文长度限制

## 四、多计划选择（Section 4）

1. **多计划生成**
   - **Self-consistency**：通过解码过程中的采样策略（温度采样、top-k 采样）获取多条推理路径
   - **Tree-of-Thought (ToT)**：提出 sample 和 propose 两种计划生成策略
   - **Graph-of-Thought (GoT)**：扩展 ToT，支持思维聚合变换
   - **LLM-MCTS / RAP**：以 LLM 作为蒙特卡洛树搜索（MCTS）的启发式策略函数

2. **最优计划选择**
   - **Self-consistency**：多数投票策略
   - **ToT**：支持 BFS/DFS 等树搜索算法，用 LLM 评估多个动作
   - **LLM-MCTS / RAP**：基于蒙特卡洛树搜索算法进行选择
   - **LLM-A\***：利用经典 A\* 算法，以切比雪夫距离作为启发式代价函数

3. **讨论**
   - 优势：可扩展性好，在广阔搜索空间中更全面地探索潜在解
   - 局限：计算成本高，尤其对大 token 模型；LLM 排名能力仍需验证；随机性影响选择的一致性和可靠性

## 五、外部规划器辅助规划（Section 5）

1. **符号规划器（Symbolic Planner）**
   - **LLM+P**：LLM 将任务形式化为 PDDL 语言，再由 Fast-Downward 求解器执行规划
   - **LLM-DP**：专为动态交互环境设计，接收环境反馈后形式化为 PDDL 并用 BFS 求解器生成计划
   - **LLM+PDDL**：增加人工验证步骤检查 LLM 生成的 PDDL 模型；利用 LLM 生成的计划作为初始启发式解加速局部搜索
   - **LLM+ASP**：将自然语言问题转化为原子事实和 ASP 问题，用 CLINGO 求解器生成计划

2. **神经规划器（Neural Planner）**
   - **DRRN**：通过强化学习训练策略网络，将规划过程建模为马尔可夫决策过程
   - **Decision Transformer (DT)**：通过模仿学习克隆人类决策行为
   - **CALM**：语言模型与 RL 神经规划器的早期结合方案
   - **SwiftSage** ⭐：基于认知心理学双系统理论，分为慢思考（LLM 复杂推理）和快思考（DT 模型快速生成），错误时切换

3. **讨论**
   - LLM 主要扮演辅助角色（解析文本反馈、提供推理信息）
   - 符号系统优势：理论完备性、稳定性、可解释性
   - LLM 加速了符号模型的建立过程，统计 AI 与 LLM 的结合是未来重要趋势
   - 神经规划器在特定领域表现优秀但在训练数据稀缺时泛化能力不足

## 六、反思与优化（Section 6）

1. **Self-Refine**：迭代式的生成—反馈—优化流程，LLM 自行生成反馈并调整计划

2. **Reflexion**：扩展 ReAct，引入评估器评估轨迹，LLM 在错误检测时生成自我反思辅助纠错

3. **CRITIC**：利用外部工具（知识库、搜索引擎）验证 LLM 生成的动作，借助外部知识进行自我纠错，显著减少事实性错误

4. **InteRecAgent (ReChain)**：LLM 评估推荐智能体的响应和工具使用计划，总结错误反馈，决定是否重启规划

5. **LEMA**：收集错误规划样本，使用更强大的 GPT-4 进行纠正，用纠正后的样本微调 LLaMA 模型

6. **与强化学习的类比及讨论** ⭐
   - 自我反思策略类似于强化学习原理：智能体作为决策者（策略网络），环境反馈触发策略更新
   - 关键区别：深度 RL 通过修改模型参数更新策略，LLM 智能体通过自我反思产生文本反馈
   - **重要局限**：文本形式的策略更新缺乏收敛保证，无法证明持续反思能最终导向目标

## 七、记忆增强规划（Section 7）

1. **基于 RAG 的记忆（RAG-based Memory）**
   - **Generative Agents**：以文本形式存储日常经验，基于新近性和相关性检索记忆
   - **MemoryBank / TiM / RecMind**：使用文本编码模型将记忆编码为向量，建立索引结构（如 FAISS），以当前状态描述作为查询检索
   - **MemGPT**：借鉴计算机架构的多级存储概念，将 LLM 上下文抽象为 RAM，额外存储结构视为磁盘，LLM 自主决定检索或保存
   - **REMEMBER**：以 Q 值表形式存储历史记忆（环境、任务、动作、Q 值元组），检索正负记忆辅助规划

2. **具身记忆（Embodied Memory）**
   - 通过微调 LLM 将历史经验样本嵌入模型参数
   - 利用参数高效微调（PEFT）技术（如 LoRA、QLoRA、P-tuning）降低成本
   - **CALM**：用真实动作轨迹微调 GPT-2，记忆规划相关信息
   - **TDT**：用 MDP 数据微调 Text Decision Transformer，在 ScienceWorld 上表现更好
   - **AgentTuning**：将多任务规划轨迹组织为对话形式微调 LLaMA，在未见规划任务上显著提升

3. **讨论**
   - RAG 方法优势：实时、低成本的外部记忆更新（自然语言文本形式）
   - RAG 方法局限：依赖检索算法准确性
   - 微调方法优势：通过参数修改提供更大的记忆容量
   - 微调方法局限：记忆更新成本高，难以保留细粒度细节
   - 记忆生成严重依赖 LLM 的生成能力，通过自我生成记忆改进较弱 LLM 智能体仍是挑战

## 八、评估（Section 8）

1. **交互式游戏环境**
   - Minecraft：智能体收集材料创造工具，工具数量为评估指标
   - 文本交互环境（ALFWorld、ScienceWorld）：以成功率或奖励为评估指标

2. **交互式检索环境**
   - 基于 Wikipedia 的问答（HotPotQA、FEVER）
   - Web 浏览任务（WebShop、Mind2Web、WebArena），以成功率为指标

3. **交互式编程环境**
   - AgentBench、MiniWoB++：测试智能体解决计算机相关问题的规划能力

4. **评估环境局限性**
   - 缺乏细粒度评估，主要依赖最终完成状态
   - 大多数模拟环境只有一条"黄金"路径，不像真实世界存在多条完成路径

5. **实验发现** ⭐（Table 2）
   - **性能随开销增长**：CoT-SC、ReAct、Reflexion 因涉及多计划/额外思考/反思，token 消耗更多但性能提升

## 九、结论与未来方向（Section 9）

1. **核心结论**
   - LLM 智能体规划能力的五大方向（任务分解、多计划选择、外部规划器辅助、反思优化、记忆增强）各有优劣
   - 性能提升与计算开销正相关

2. **五大未来挑战** ⭐
   - **幻觉问题（Hallucinations）**：规划过程中 LLM 常产生幻觉，导致不合理计划、不忠实于任务提示或无法遵循复杂指令
   - **生成计划的可行性（Feasibility）**：LLM 基于统计学习优化下一个词概率，难以遵守复杂约束，可能缺乏可行性；将 LLM 与符号规划模型连接而不改变 LLM 本身是有前途的方向
   - **生成计划的效率（Efficiency）**：现有方法基于 LLM 输出贪心规划，不考虑计划效率，未来需引入效率评估模块
   - **多模态环境反馈（Multi-Modal Feedback）**：真实环境反馈常包含图像、音频等多模态信息，难以用自然语言描述，需结合多模态大模型发展
   - **细粒度评估（Fine-grained Evaluation）**：现有基准缺乏逐步评估，环境反馈过于简化，可利用高智能模型设计更现实的评估环境

## 一些通俗理解

### **一句话总结**

这篇论文是一篇综述，系统梳理了"如何让大语言模型（LLM）学会做计划"的各种方法，把它们分成了五大类，并分析了各自的优缺点和未来挑战。

### **先理解背景：什么是"规划"？**

想象你要做一道复杂的菜——你需要先想好步骤：买菜、洗菜、切菜、炒菜、装盘。这个"想好步骤"的过程就是**规划**。对于AI智能体来说，规划就是面对一个任务时，生成一串有序的动作来完成它。

以前做规划主要靠两种老方法：一种是**符号方法**（像填表格一样把问题写成严格规则），太死板，一个错就全崩；另一种是**强化学习**（让AI反复试错学习），太费时间和数据。

后来大语言模型（比如GPT系列）出现了，它们在推理和理解上很强，所以大家开始想：能不能让LLM当智能体的"大脑"来做规划？这篇论文就是全面梳理这条路上的各种方法。

### **用生活类比来理解五种方法**

假设你要**从北京去三亚旅游**，这是一个复杂的任务：

#### **1. 任务分解——把大任务拆成小任务**

就像把"去三亚旅游"拆成：订机票→订酒店→收拾行李→去机场→入住→玩景点。有两种拆法：

- **先拆完再执行**：一开始就把所有子任务列好，再逐步执行。好处是思路清晰，坏处是万一中间出了岔子（比如机票取消了），整个计划就废了。
- **边拆边执行**：先想第一步，做完看情况再想下一步。好处是灵活应变，坏处是走太多步可能忘了最初的目标。

代表方法：CoT（思维链）、ReAct、HuggingGPT 等。

#### **2. 多计划选择——多想几个方案，挑最好的**

不要只做一个计划，而是多想几套方案（比如飞机去、火车去、自驾去），然后从中选最优的。怎么选呢？可以用投票（大家觉得哪个好就选哪个），也可以用搜索树（像下棋一样往前推演几步看哪条路最好）。

代表方法：Self-consistency（多数投票）、ToT（思维树）、GoT（思维图）、MCTS 等。

#### **3. 外部规划器辅助——请专业帮手**

LLM虽然聪明，但在严格约束下（比如数学规划、逻辑推理）可能不够靠谱。所以让LLM负责"翻译"任务（把自然语言变成形式化语言），再交给专业的规划工具来算。就像你自己想不好行程，先描述需求，然后交给专业旅行社来排。

代表方法：LLM+P（用PDDL符号规划器）、SwiftSage（快思考用小模型，慢思考用LLM）等。

#### **4. 反思与优化——错了就改**

第一次做的计划不靠谱没关系，关键是能从错误中学到东西。做完后发现哪里出了问题，反思一下原因，然后修改计划重新来。就像你第一次旅游忘带防晒霜被晒伤了，下次就知道带上。

代表方法：Reflexion（自我反思）、Self-Refine（自我优化）、CRITIC（借助外部工具验证）等。

#### **5. 记忆增强——好记性帮大忙**

把以前积累的经验存起来，下次遇到类似任务时翻出来参考。有两种存法：

- **外挂笔记本**：把经验存在外面，需要时检索。便宜快速，但找得准不准是个问题。
- **刻进脑子里**：用过去的经验微调模型参数。记住得多，但更新成本高、细节容易丢。

代表方法：Generative Agents、MemGPT、REMEMBER、AgentTuning 等。

### **实验发现了什么？**

论文在四个基准上做了实验，三个重要发现：

1. **花得多赚得多**：用更多token（更多思考、更多尝试）的方法，效果确实更好。
2. **难题需要示范**：简单的"让我们一步步想"在复杂任务上不够用，还是需要给LLM一些示例。
3. **反思很有用**：特别是对复杂任务，反思纠错带来的成功率提升很明显，虽然要多花一倍的token。

### **还有哪些难题没解决？**

论文最后指出了五个未解决的挑战：

- **幻觉**：LLM有时会"编造"不存在的动作或物品，导致计划不靠谱。
- **可行性**：LLM生成的计划看着合理，但实际可能行不通（比如要求操作环境中不存在的物品）。
- **效率**：目前的方法只管"能不能完成任务"，不太关心"怎样最省事地完成"。
- **多模态反馈**：真实世界的反馈不只是文字，还有图片、声音等，LLM目前主要处理文字，应对多模态有困难。
- **评估太粗糙**：现在的评估只看"最终做没做成"，缺乏对每一步的细致评价，而且模拟环境太简单，离真实世界差距大。

总的来说，这篇论文像是给"LLM做规划"这个领域画了一张全景地图——标出了五条主要路线，说明了每条路走到哪了、有什么坑，以及还有哪些路没人走过。
