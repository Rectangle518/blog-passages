# ReAct: Synergizing Reasoning and Acting in Language Models

## 一、引言（Introduction）
   - 1.1 研究背景：人类智能中推理与行动的协同机制
     - 内部言语（inner speech）在认知中的作用：自我调节、策略制定、工作记忆维护
     - 日常示例：烹饪中推理（跟踪进度、处理异常）与行动（查阅食谱、检查食材）的交替
   - 1.2 现有方法的分离困境
     - 推理方向：Chain-of-Thought（CoT）——静态黑盒，易产生事实幻觉与错误传播
     - 行动方向：LLM用于规划与动作生成——缺乏高层目标推理与工作记忆维护
   - 1.3 研究问题：能否让LLM以交错方式同时生成推理轨迹与任务动作，实现协同增益？
   - 1.4 **核心创新** ★：ReAct范式——推理与行动交错生成，"reason to act"与"act to reason"双向增强

## 二、ReAct方法（Method）

### 2.1 问题形式化
   - 标准agent设定：观测 $o_t \in O$，动作 $a_t \in A$，策略 $\pi(a_t|c_t)$，上下文 $c_t = (o_1, a_1, \ldots, o_t)$
   - **关键设计** ★：扩展动作空间 $\hat{A} = A \cup L$，其中 $L$ 为语言空间
     - "thought"（思考）属于语言空间，不改变外部环境，无观测反馈
     - thought的作用：更新上下文 $c_{t+1} = (c_t, \hat{a}_t)$，支持后续推理与行动

### 2.2 Thought的多种功能类型
   - 目标分解与行动计划制定
   - 注入常识知识
   - 从观测中提取关键信息
   - 跟踪进度与转换行动计划
   - 处理异常与调整计划

### 2.3 两种Thought排布策略
   - **密集交替**（Dense thought）：知识密集推理任务——Thought-Action-Observation多步交替
   - **稀疏异步**（Sparse thought）：决策任务——LLM自主决定thought出现位置

### 2.4 实现方式
   - 基座模型：PaLM-540B（冻结），Few-shot prompting
   - 每个in-context示例为人工编写的"动作-思考-观测"轨迹
   - **设计特点** ★：直观易设计、通用灵活、性能鲁棒、人类可对齐可控

## 三、知识密集推理任务实验

### 3.1 实验设置

### 3.2 对比方法

   - CoT（Reason Only）：移除action和observation，纯推理
   - CoT-SC：CoT + 自一致性采样（21条轨迹，温度0.7）

### 3.3 ReAct + CoT-SC 组合策略 ★
   - ReAct → CoT-SC：ReAct在给定步数内无法回答时，回退到CoT-SC
   - CoT-SC → ReAct：CoT-SC多数答案出现次数 < n/2 时，回退到ReAct
   - **设计动机**：ReAct更事实可信，CoT推理结构更灵活——互补组合

### 3.4 微调实验

### 3.5 主要结果 ★

   - ReAct vs CoT：Fever上ReAct更优（60.9 vs 56.3），HotpotQA上略逊（27.4 vs 29.4）
   - **最佳组合**：ReAct + CoT-SC在两个任务上均达到最优

### 3.6 人类分析：成功与失败模式 ★

   - ReAct的搜索失败占23%：无信息检索使推理脱轨
   - **关键结论** ★：事实性（ReAct）与灵活性（CoT）之间存在本质权衡

### 3.7 微调缩放结果 ★

## 一些通俗理解

### **ReAct论文：让AI学会"边想边做"**

想象你在厨房做一道菜。你不会像机器人一样机械地执行步骤——你会在做的同时思考："菜切好了，接下来该烧水了""盐用完了，用酱油代替吧""面团怎么和？让我查一下食谱"。你一边动手，一边在脑子里推理，两者互相帮助、缺一不可。

这篇论文的核心思想就是这么简单：**让大语言模型也学会"边想边做"。**

### **之前的方法有什么问题？**

在ReAct之前，AI解决问题主要有两种方式，但它们是"各干各的"：

**第一种：只想不做（Chain-of-Thought，思维链）**。模型在脑子里一步步推理，但从来不动手去查证。这就像你做菜全凭记忆，从不翻食谱也不开冰箱确认食材——结果就是容易"一本正经地胡说八道"（论文称之为"幻觉"）。模型可能编造出完全不存在的事实，而且还特别自信。

**第二种：只做不想（Act-only）**。模型直接执行动作，搜索信息、点击按钮，但从来不停下来想一想为什么要这么做、下一步该干什么。这就像一个人在厨房里疯狂开柜子、翻冰箱，却没有计划——很容易迷失方向，反复做无用功。

### **ReAct怎么解决的？**

ReAct的核心创新就一句话：**让模型交替产生"思考"和"行动"。**

打个比方，面对一个复杂问题"科罗拉多造山运动东部区域延伸到的山脉的海拔是多少？"，ReAct的解题过程是这样的：

1. **思考**：我需要先找到科罗拉多造山运动东部延伸到了哪个山脉
2. **行动**：搜索"科罗拉多造山运动"
3. **观察**：维基百科说它东部延伸到了……
4. **思考**：好，现在我知道是XX山脉了，接下来查它的海拔
5. **行动**：搜索"XX山脉"
6. **观察**：该山脉海拔……
7. **思考**：找到了，海拔是XXXX米，这就是答案
8. **行动**：提交答案"XXXX"

每一步思考都帮模型理清"我要干什么"，每一次行动都帮模型获取"我不知道的信息"，两者交替推进，问题就迎刃而解了。

### **效果怎么样？**

论文在四类任务上做了实验，结果很有说服力：

**知识问答与事实验证（HotpotQA / Fever）**：ReAct比"只做不想"的方法好得多，因为它知道该搜什么、怎么搜。跟"只想不做"的CoT相比，ReAct最大的优势是**不容易编造事实**——因为不确定的东西它会去查。但CoT在推理结构上更灵活，所以两者结合效果最好。

**交互决策（ALFWorld / WebShop）**：这才是ReAct真正大放异彩的地方。在模拟家庭任务的ALFWorld游戏中，ReAct只用了2-3个示例，就达到了71%的成功率，而用10万条数据训练的模仿学习方法只有37%。在WebShop网购任务中，ReAct比强化学习方法高了10个百分点。

### **一个特别有意思的发现**

论文做了一个消融实验，比较ReAct和一种叫"Inner Monologue"（内心独白）的方法。后者也会"思考"，但它的思考仅限于复述外部反馈（"我现在拿到了杯子，下一步要找台灯"）。而ReAct的思考更自由——它会用常识推理（"台灯一般放在书桌上"）、会判断进度（"这个子目标完成了，该进行下一个了"）。结果ReAct 71% vs Inner Monologue 53%，差距巨大。

这说明：**真正有用的"思考"不只是对现状的描述，而是调用你的常识和经验来做判断。**

### **还有什么不足？**

ReAct也不是万能的。它在推理任务上有时比不过纯CoT，因为"想一步、做一步"的固定节奏限制了推理的灵活性。而且模型有时会陷入重复循环——反复生成同样的思考和动作，跳不出来。另外，纯prompting方式离专门的监督学习方法还有差距，微调后才能发挥更大潜力。

### **为什么这篇论文重要？**

ReAct提出的思想虽然简单，但影响深远。它打破了"推理"和"行动"的界限，启发了后来一系列Agent框架的设计——从AutoGPT到各种工具调用的AI助手，本质上都是在践行"边想边做"的理念。可以说，ReAct是现代AI Agent的奠基性工作之一。
