

# 大模型介绍

## 1. 认识模型
   - 模型的本质定义：从数据中学习规律的"数学函数"或"程序"
   - 核心比喻："超级加工厂"——训练师提供海量数据，模型自行摸索规则
   - 模型的关键特点
     - 1. 特定任务：一个模型通常只擅长一件事（如图像识别、天气预测、情感分析）
     - 2. 需要"标注数据"：训练依赖大量"标准答案"
     - 3. 参数较少：模型复杂度和能力相对有限

## 2. 认识大语言模型
### 2.1 什么是大语言模型
   - 定义：基于大规模神经网络（数十亿至万亿参数），通过自监督/半监督方式对海量文本训练的语言模型
   - 核心概念拆解
     - **神经网络**：模仿人脑的"团队工作流程"，由大量参数和连接组成的复杂决策系统
     - **自监督学习**：模型从数据本身找规律，自己给自己当老师（"完形填空"式学习）
     - **半监督学习**：少量指导+大量自学的结合模式
     - **语言模型**：计算"接下来最可能说什么"的模型（"超级自动补全"）
   - 大语言模型的核心特点 ⭐
     - 规模巨大：参数量达数十亿至万亿级别
     - 通用性强：具备"涌现"能力，可举一反三应用于多种任务
     - 训练方式不同：主要使用自监督学习，从海量无标注文本中学习
     - 交互方式革命：通过自然语言指令（Prompt）直接交互

### 2.2 主流的大语言模型
   - GPT-5（OpenAI）：400k上下文，128k最大输出，擅长复杂推理与创意写作
   - DeepSeek R1（深度求索）：开源，专注逻辑推理与数学求解，128K上下文，20+语言
   - Qwen2.5-72B-Instruct（阿里巴巴）：擅长代码生成、结构化数据处理、角色扮演，29种语言
   - Gemini 2.5 Pro（Google）：多模态融合标杆，支持图像/代码/文本混合输入

### 2.3 LLM的能力 ⭐
   - **语言大师**：理解与创造的革命——真正读懂人类语言的上下文、情感、潜台词，进行高质量创作
   - **知识巨人**：拥有"全互联网"的记忆——被压缩的、可对话的"互联网知识库"，形成立体知识网络
   - **逻辑与代码巫师**：从思维到实现的跨越——超越"文科"进入精确推理的"理科"领域
   - **多模态先知**：开启"全感知"AI大门——打破文本界限，连接视觉、听觉世界

### 2.4 提示词编写技巧
#### 2.4.1 CO-STAR结构化框架 ⭐
   - 来源：新加坡政府技术局（GovTech）开发
   - 六个维度：Context（背景）、Objective（目标）、Steps（步骤）、Tone（风格）、Audience（受众）、Response（输出格式）
   - 核心思想：换位思考，清晰、具体、无歧义地传达需求

#### 2.4.2 少样本提示/多样本提示
   - 核心思想：通过输入-输出示例"教"AI想要的格式、风格和逻辑
   - 适用场景：格式固定、风格独特、逻辑复杂的任务

#### 2.4.3 思维链提示 ⭐
   - Few-shot-CoT（少样本思维链）：在示例中同时提供推导过程和答案
   - 核心思想：要求AI"展示工作过程"而非直接给出答案
   - 适用场景：数学题、逻辑推理、复杂决策
   - 关键结论：提供的范例越详细，AI模仿越准确；但稳定性有待提升

#### 2.4.4 自动推理与零样本链式思考（Zero-shot-CoT）
   - 核心思想：通过"请一步步进行推理并得出结论"等指令，强制AI先推理再回答
   - 原理：引导模型的"注意力机制"，为自身创造更丰富的推理上下文
   - ⭐ 重要结论：根据《Large Language Models are Zero-Shot Reasoners》论文，Few-shot-CoT比Zero-shot-CoT准确率更高

#### 2.4.5 自我批判与迭代
   - 核心思想：将"生成"和"评审"两步骤分离，利用AI批判性思维提升质量
   - 适用场景：代码审查、文案优化、论证强化、安全检查

   - **技巧组合策略**：CO-STAR框架 + 思维链指令 + 少样本示例 + 自我审查

### 2.5 为什么LLM如此重要
   - 生产力革命的"加速器"：自动化语言和知识工作，核心价值是增强人类（Human Augmentation）
   - 人机交互的"新范式"：从"人适应机器"到"机器适应人"
   - 产业智能化的"核心引擎"：赋能教育、医疗、法律、文创等千行百业

### 2.6 LLM的接入方式
#### 2.6.1 API远程调用 ⭐
   - 最主流、最便捷的接入方式
   - 流程：注册获取API Key → 查阅API文档 → 构建HTTP请求 → 发送请求并处理响应
   - 代表厂商：OpenAI、Anthropic、Google、百度、阿里、智谱AI
   - 实践示例：OpenAI API调用（curl命令与SDK方式）

#### 2.6.2 本地部署（开源模型）
   - 将开源模型部署在自有硬件环境
   - 流程：获取模型 → 准备GPU环境 → 选择推理框架 → 启动服务
   - 推理框架：vLLM、TGI、Ollama、LM Studio
   - 实践示例：Ollama安装 → 拉取模型（如DeepSeek-R1）→ 测试与接口调用

#### 2.6.3 SDK和官方客户端库
   - 对API接入的封装和简化，提供更符合编程习惯的函数库
   - 实践示例：OpenAI Python SDK的使用

#### 2.6.4 接入方式选择与原生LLM的局限性 ⭐
   - 选择依据：数据敏感性、技术实力与资源、成本与规模、定制需求
   - **原生LLM四大局限**：
     1. 输入长度限制（固定Token上限）
     2. 缺乏私有知识（训练数据有截止日期，不含私人数据）
     3. 复杂任务处理能力弱（"一问一答"接口，多步骤需自行编排）
     4. 输出格式不可控（可能产生格式错误或不合规内容）
   - ➡️ 引出LangChain框架的诞生动机：系统性解决上述问题

## 3. 认识嵌入模型
### 3.1 什么是嵌入模型
   - 本质：表示型模型，为输入文本创建富含语义的数值表示（向量）
   - 与大语言模型的区别：LLM是生成式模型（创造文本），嵌入模型是表示型模型（将符号转换为向量）
   - 核心思想：将人类世界的符号转换为计算机可理解的向量，并保留语义和关系
   - ⭐ 关键结论：既然是"数学语言"，就可以用数学方式比较向量，实现**度量语义**的目的

### 3.2 嵌入模型应用场景 ⭐
   - **语义搜索**：通过向量相似度检索，超越关键词匹配的限制
   - **检索增强生成（RAG）**：先语义搜索知识库，再将相关内容交给LLM生成答案——当前LLM应用的**核心模式**
   - **推荐系统**：用户与物品向量化，通过相似度实现精准推荐
   - **异常检测**：正常数据向量聚集，远离聚集区的向量为异常点

### 3.3 主流的嵌入模型
   - text-embedding-3-large（OpenAI）：默认3072维，支持降维，8192 Token输入
   - Qwen3-Embedding-8B（阿里巴巴）：开源，100+语言，32k上下文，最高4096维
   - gemini-embedding-001（Google）：100+语言，默认3072维，可选降维

### 3.4 嵌入模型接入方式
#### 3.4.1 API接入（闭源模型）
   - 流程：注册获取API Key → 安装SDK或构造HTTP请求 → 调用API处理响应
   - 实践示例：OpenAI Embeddings API（curl请求与Python SDK）

#### 3.4.2 本地部署（开源模型）
   - 流程：准备GPU环境 → 下载模型权重 → 使用transformers等库加载推理
   - 适用场景：数据隐私、成本控制有更高要求的场景
   - 实践建议：初创项目从API开始，规模化或合规需求时再迁移本地

   - ⭐ 与原生LLM相似的后续问题：获取向量后需存入向量数据库（Chroma、Milvus、Pinecone等），LangChain提供统一的嵌入模型接口便于切换
