
# 今日论文

## 一、 产品定位

产品旨在帮助计算机领域的研究者、工程师与学生，解决学术信息过载、文献阅读效率低、知识沉淀难三大核心痛点。通过每日智能推送、深度知识库、可视化知识网络与协作讨论，将碎片化的论文阅读转化为系统性的知识积累。


## 二、 核心功能模块

### 模块一：论文推送（支持订阅与个性化）

**目标**：从“被动接收信息”升级为“主动获取精准内容”。

-   **多源数据接入**
    -   支持arXiv、顶级会议（NeurIPS、ICML、CVPR、ACL等）、机构博客（Google AI、DeepMind等）RSS源。
    -   用户可按**分类**、**关键词**、**作者**进行精细订阅。

-   **个性化推荐引擎**
    -   基于用户的阅读历史、收藏、点赞行为，构建动态兴趣画像。
    -   每日推送列表按**预测相关度**排序，而非单纯按时间倒序。
    -   每篇推送附带**核心贡献一句话总结**、**与本领域关联度评分**，辅助快速决策。

-   **推送渠道**
    -   （可选）支持邮件摘要（每日/每周）、飞书/企业微信机器人、Telegram Bot、微信小程序订阅。
    -   高优先级命中（如用户关注的作者发布新论文）支持即时推送。


### 模块二：知识库与检索

**目标**：构建可交互的科研知识库，支持自然语言查询与语义检索。

-   **论文结构化存储**
    -   存储论文的元数据：标题、作者、摘要、PDF链接、代码仓库、发表时间、会议/期刊来源。
    -   （可选）支持全文PDF上传与解析（可选，针对用户手动导入或重点论文）。

-   **语义检索与RAG问答**
    -   将论文摘要（可选：全文）向量化，支持**自然语言查询**。
    -   示例：“过去三个月有哪些关于MoE推理优化的论文？请对比它们的核心方法。”
    -   回答内容附带**引用来源**（具体论文及段落），确保可追溯。

-   **（可选）个人/团队笔记系统**
    -   支持对单篇论文添加**私有笔记**、**标签**（如“待复现”“组会讨论”）。
    -   笔记支持Markdown格式，可与论文原文双向链接。


### 模块三：论文讨论区

**目标**：将单点阅读转化为社区协作，沉淀群体智慧。

-   **论文级评论区**
    -   每篇论文下设有**讨论区**，用户可发表短评、提问、分享复现经验。
    -   用户可以设置我关注的人/关注我的人可见、某个分组的人可见、所有人可见。

-   **团队/课题组空间**
    -   支持创建私有团队（如实验室、项目组），成员可在空间内共享：
        -   团队必读论文列表
        -   组会讨论材料归档
        -   论文复现进度跟踪
    -   新成员加入时可查看团队完整阅读历史与技术讨论记录。

-   **互动与激励**
    -   支持评论点赞、收藏、@提及成员。
    -   可设“周活跃贡献者”标识，提升参与度。


### 模块四：论文参考树可视化

**目标**：将孤立的单篇论文串联为技术演进图谱，帮助用户理解知识脉络。

-   **引文网络构建**
    -   自动抓取每篇论文的**参考文献**与**施引文献**（通过Semantic Scholar、CrossRef等API）。
    -   支持**向前追溯**（本文依赖了哪些关键工作）与**向后追踪**（本文发表后影响了哪些后续研究）。

-   **交互式可视化**
    -   以**力导向图**或**树状图**展示引用关系，节点大小代表被引量/影响力。
    -   点击节点可预览论文摘要，支持一键跳转至详情页。
    -   支持**高亮关键路径**：例如“Transformer演进路线”，系统可自动标注从Attention、Transformer到GPT、Llama的脉络。

-   **领域热力图**
    -   在时间轴上展示某技术方向（如“多模态大模型”）的论文密度变化，直观感知领域热度趋势。


### 模块五：专业术语单词本

**目标**：在阅读中自然积累专业词汇，降低英文文献阅读障碍。

-   **自动提取术语**
    -   支持用户手动添加划词内容。
    -   当用户收藏或标记某篇论文时，系统通过LLM自动提取文中**核心专业术语**（如“attention mechanism”、“scaling law”、“sparse MoE”），并询问是否加入单词本。
    

-   **术语解释与关联**
    -   每个术语提供**详细解释**，包括定义、背景、应用场景等。
    -   每个单词自动关联**出现该术语的论文列表**，点击可跳转至原文上下文，实现“在具体语境中理解术语”。
  

## 三、 技术架构建议（简述）

| 层次 | 技术选型 |
|------|----------|
| 数据采集 | arXiv API、Semantic Scholar API、RSS解析（Feedparser）、定时任务（APScheduler） |
| 后端服务 | FastAPI（Python） |
| 数据库 | PostgreSQL（结构化数据）、pgvector（向量检索）、Redis（缓存与去重） |
| 向量化模型 | BAAI/bge-large-zh-v1.5（中英双语）或OpenAI text-embedding-3-small |
| 图数据库 | Neo4j（引文关系存储与可视化） |
| 大模型API | GPT-4o / Claude / 本地Qwen2.5-14B（用于总结生成、术语提取、RAG问答） |
| 存储 | MinIO / 阿里云OSS（PDF原文、用户头像等） |
| 前端 | Next.js + TailwindCSS（Web端），微信小程序（移动端轻量触达） |
| 部署 | Docker + GitHub Actions + 阿里云/腾讯云轻量服务器 |

## 四、 分阶段实施建议

| 阶段 | 聚焦功能 | 目标 |
|------|----------|------|
| **Phase 1（MVP）** | 论文推送（基础订阅+邮件） + 结构化知识库（PostgreSQL） + 单词本（手动添加）+ 论文讨论区 | 跑通“采集-存储-推送”闭环，验证核心流程 |
| **Phase 2** | 个性化推荐 + RAG语义检索 + 论文引用树可视化 | 从“推送”升级为“可交互知识库” |
| **Phase 3** | 团队协作空间 + 自动术语提取 | 强化差异化功能，构建护城河 |


## 五、 核心竞争力总结

1.  **个性化精炼**：不是简单聚合，而是懂用户的学术助手。
2.  **知识网络化**：不只是单篇论文，而是可追溯、可探索的技术脉络。
3.  **可交互知识库**：不仅能查，还能问（自然语言问答），检索效率远高于传统关键词搜索。
4.  **团队协作沉淀**：将个人工具扩展为团队基础设施，提升用户粘性与迁移成本。
